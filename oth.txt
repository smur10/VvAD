Обоснование: Использование идентификаторов и признаков-утечек приводит к переобучению модели и получению нереалистично высоких результатов на валидации. Удаление таких признаков является обязательным этапом при подготовке данных.

C1. Разбиение выборки
Разбиение выборки на обучающую и валидационную было выполнено в соотношении 75% / 25%. Данное соотношение было выбрано с учётом относительно небольшого объёма данных (178 объектов после очистки). Оно позволяет обеспечить достаточный объём данных для обучения моделей, сохраняя при этом репрезентативную валидационную выборку для оценки качества. При разбиении была использована стратификация (stratify=y_encoded) для сохранения исходного распределения классов.
Целевая переменная WineClass была закодирована в числовой формат с помощью LabelEncoder, так как большинство алгоритмов машинного обучения работают с числовыми метками классов.
На этапе предобработки была создана универсальная схема обработки данных с помощью Pipeline и ColumnTransformer:
•	Для числовых признаков: заполнение пропусков медианой и стандартизация.
•	Для категориальных признаков: заполнение наиболее частым значением и One-Hot Encoding.
Для обеспечения воспроизводимости результатов при разбиении данных был задан параметр random_state=42. Это позволяет получать одинаковые обучающую и валидационную выборки при каждом запуске кода, что делает процесс моделирования контролируемым и воспроизводимым.
Такой подход позволяет избежать утечки данных из валидационной выборки и делает процесс предобработки воспроизводимым.

C2. Построение и выбор модели прогнозирования
В рамках работы была построена модель Логистической регрессии. Данная модель была выбрана в качестве базовой по следующим причинам: она является одной из наиболее интерпретируемых моделей классификации, имеет относительно небольшое количество гиперпараметров и хорошо работает после проведения предварительной обработки данных.
Модель была реализована с использованием Pipeline, что позволяет объединить этапы предобработки и обучения в единый воспроизводимый процесс. В качестве предобработчика использовался ранее созданный объект preprocessor, включающий заполнение пропусков и масштабирование числовых признаков, а также кодирование категориальных признаков.
При создании модели LogisticRegression были использованы следующие параметры:
•	max_iter=5000 — увеличенное количество итераций для обеспечения сходимости алгоритма;
•	random_state=42 — задано для обеспечения воспроизводимости результатов;
•	class_weight='balanced' — использован для автоматической корректировки весов классов с учётом их дисбаланса в обучающей выборке.
Выбор метрик качества
Для оценки качества модели были использованы следующие метрики:
•	Accuracy — доля правильно классифицированных объектов. Данная метрика является базовой и позволяет получить общее представление о качестве модели.
•	F1-score (weighted) — средневзвешенное значение F1-меры. Данная метрика была выбрана как основная, поскольку она учитывает как точность (precision), так и полноту (recall) и является более информативной при наличии дисбаланса классов, чем Accuracy.
•	classification_report — полный отчёт по метрикам precision, recall и F1-score для каждого класса в отдельности. Данный отчёт позволяет провести более детальный анализ качества классификации по каждому классу.
Результаты модели Logistic Regression
На валидационной выборке модель показала следующие результаты:
•	Accuracy: 0.933
•	F1-score (weighted): 0.93

Модель продемонстрировала высокое качество классификации. Наиболее стабильные результаты наблюдаются для классов A и C — для этих классов recall достигает 1.00, то есть модель правильно определяет все объекты данных классов.
Для класса B наблюдается высокая точность (precision = 1.00), однако recall составляет 0.83. Это означает, что часть объектов класса B модель относит к другим классам. Данное поведение может быть связано с особенностями распределения класса B и его близостью к другим классам в пространстве признаков.
В целом, модель Логистической регрессии показала хороший результат и может рассматриваться как сильный baseline для дальнейшего сравнения с более сложными моделями.
C3. Оптимизация модели
Для повышения качества модели Логистической регрессии была проведена оптимизация её гиперпараметров с использованием метода GridSearchCV с 5-кратной кросс-валидацией.
Цель оптимизации — подобрать такие значения гиперпараметров, которые обеспечивают наилучшее качество модели на кросс-валидации. В процессе оптимизации подбирались следующие гиперпараметры:
•	C — коэффициент регуляризации. Данный параметр контролирует силу регуляризации: меньшие значения соответствуют более сильной регуляризации и более простой модели, большие значения — более слабой регуляризации и более сложной модели.
•	penalty — тип регуляризации (l1 или l2). Различные типы регуляризации по-разному влияют на веса признаков.
•	solver — алгоритм оптимизации (liblinear или lbfgs). Выбор алгоритма зависит от типа регуляризации и влияет на скорость и качество обучения.
Поскольку не все комбинации параметров penalty и solver являются совместимыми, была сформирована параметрическая сетка, состоящая из двух отдельных словарей.
Результаты оптимизации
В результате проведения поиска по сетке гиперпараметров были определены следующие оптимальные значения:
•	C = 0.1
•	penalty = 'l2'
•	solver = 'liblinear'
Лучшая средняя точность модели на кросс-валидации составила 0.977. Однако при проверке на независимой валидационной выборке accuracy оптимизированной модели составила 0.933, что соответствует уровню базовой (неоптимизированной) модели.
Анализ результатов оптимизации
Отсутствие прироста качества на валидационной выборке, несмотря на высокие показатели на кросс-валидации, может быть обусловлено несколькими факторами. Во-первых, относительно небольшой размер датасета приводит к высокой дисперсии оценок при кросс-валидации, из-за чего результаты на кросс-валидации могут быть оптимистичными. Во-вторых, базовая модель Логистической регрессии уже демонстрировала достаточно высокое качество классификации, что ограничивает потенциал для существенного улучшения. В-третьих, возможно лёгкое переобучение модели под особенности обучающих фолдов в процессе кросс-валидации.

C2. Построение и выбор модели прогнозирования
В качестве модели глубокого обучения была выбрана Multi-Layer Perceptron Classifier (MLPClassifier). Данная модель была выбрана для демонстрации применения алгоритмов глубокого обучения при решении задачи многоклассовой классификации.
Модель была реализована с использованием Pipeline. Архитектура нейронной сети состояла из двух скрытых слоёв с количеством нейронов 64 и 32 соответственно (hidden_layer_sizes=(64, 32)). В качестве функции активации использовалась функция ReLU (activation='relu').
Для регуляризации модели применялся параметр alpha=0.001. Начальная скорость обучения была установлена равной 0.001 (learning_rate_init=0.001). Максимальное количество итераций обучения было увеличено до 1000 (max_iter=1000) для обеспечения сходимости алгоритма. Для предотвращения переобучения был использован механизм ранней остановки (early_stopping=True). Параметр random_state=42 был задан для обеспечения воспроизводимости результатов.

Наиболее серьёзные проблемы наблюдаются с классом B — при высокой точности (precision = 1.00) recall составляет всего 0.17. Это означает, что модель правильно определяет лишь небольшую часть объектов данного класса, относя большинство из них к другим классам.

На основании сравнения качества моделей в качестве итоговой была выбрана базовая модель Random Forest. Несмотря на проведение оптимизации гиперпараметров, базовая версия модели продемонстрировала наиболее высокое и стабильное качество на валидационной выборке.
Выбранная модель была сохранена в файл best_exam_model.pkl. Также был сохранён объект LabelEncoder (label_encoder.pkl) для преобразования числовых предсказаний в исходные названия классов. Проверка работоспособности сохранённой модели подтвердила её корректную работу.
